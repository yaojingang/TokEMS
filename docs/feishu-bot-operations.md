# 飞书大会日报接入与运维

## 接入入口

- 大会配置：`/events/:eventId/settings/feishu`。
- 组织共用连接：`/manage/settings/feishu`。
- 管理需要组织设置管理和大会数据查看权限；查看配置与日报需要组织设置读取和大会数据查看权限。

在飞书创建企业自建应用，启用机器人，开通 `im:chat:read`、`im:message:send_as_bot` 并发布生效。将机器人加入企业内部正常群，在 TokEMS 按“连接应用 → 选择接收群 → 试发并开启”完成配置。应用密钥只在后台表单输入，不写入命令记录、文档或截图。

候选凭据通过验证后才替换旧连接；替换会暂停组织内所有大会的日报。各大会重新试发后可独立开启。群列表不完整或状态未知时保留原绑定。

## 升级与运行条件

本次新增迁移 `0063_feishu_digest_delivery_v2`、`0064_feishu_manual_request_hash`。0063 会暂停已有日报订阅，保留历史记录，要求重新试发开启；旧 V1 数据仍可查看。迁移同时记录历史退款“已经成功”的观察时间上界，不填造成功发生日期。

API 与 Worker 使用同一数据库、Redis、现有集成凭据加密配置。生产后台入口必须配置有效 HTTPS 域名。沿用现有 Outbox、BullMQ 和 Worker，不增加运行服务；CLI 仅用于协助诊断。生产发布继续执行生产发布 Runbook。

Worker 每分钟扫描到期订阅与中断任务，写入 `feishu-digest:scheduler:heartbeat:v2`，有效期 180 秒。后台综合 Redis 可达性与心跳时效判断发送服务是否就绪。默认每天大会时区 09:00 发送前一完整自然日数据；首次开启安排未来最近一次发送。

飞书应用凭据、订阅、投递账本和心跳均属于运行数据，禁止纳入规范大会快照。

## 结果与恢复

| 状态                         | 后台处理                                                            |
| ---------------------------- | ------------------------------------------------------------------- |
| 等待发送、正在生成、正在发送 | 后台继续执行，可关闭页面，返回后查看结果                            |
| 等待重试                     | 系统处理明确限流或发送前服务故障；同一投递复用固定数据、卡片和 UUID |
| 无快照的生成失败             | 首次发送前且仍在 12 小时窗口内，可以重新生成                        |
| 结果待确认                   | 先在目标群查找；选择“已收到”记录人工确认，或明确确认补发            |
| 已发送                       | 保留飞书消息标识；记录恢复只补记状态，不再次发送                    |
| 配置变化或大会归档           | 取消尚未发送的旧任务；已提交给飞书的消息仍可能到达                  |

发送重试最多 5 次，首次发送后的自动重试不超过 1 小时；超过 12 小时窗口的未完成投递停止自动发送。人工补发形成新投递并关联原记录。人工确认保留原技术状态，不伪造消息标识。

## 指标解释

昨日新增与当前累计分开呈现。退款申请按申请创建时间，退款成功使用可信成功时间；开票需求按创建时间，提交资料按转入待审核的记录按申请去重。当前待办沿用退款和发票后台的筛选规则，避免把可能重叠的待办相加。

访问未覆盖完整一天时显示数据不完整；缺少可信退款时间、混合币种或异常支付流水时，相应金额显示待核对，数量继续保留。金额按业务流水统计，未表示银行结算或手续费后的到账金额。

## 验收方式

基础检查运行 `pnpm check`。持久化回归必须连接独立测试数据库和 Redis，先运行全部迁移，再执行以下测试：

```sh
pnpm --filter @conference/api exec vitest run src/common/feishu-digest.integration.test.ts
pnpm --filter @conference/worker exec vitest run src/feishu-digest-delivery.integration.test.ts src/feishu-digest.worker.test.ts src/feishu-rate-gate.integration.test.ts
pnpm --filter @conference/database exec vitest run src/feishu-digest.integration.test.ts
```

真实飞书联调需要企业应用和授权测试群。通过后台试发，核对卡片、四个业务入口及群内实际到达，再由管理员开启每日推送。CLI 直接发送不会生成 TokEMS 试发验证标记。

## 并发操作与历史数据核对

- 页面中正在编辑的接收群与发送时间绑定开始编辑时的配置版本。刷新群列表或查询发送结果会更新运行状态；提交旧版本草稿时需要刷新并重新核对，防止覆盖其他管理员的新配置。
- 群列表刷新只协调刷新开始时仍保持同一配置、目标群和运行版本的订阅。刷新期间完成的新配置或成功试发保留，由后续刷新检查。
- 发送记录的详情和结果查询分别绑定当前请求。历史记录的迟到响应不会更换当前操作对象；浏览器中的试发恢复信息只由对应投递的确定结果清除。
- 重新生成会核对应用连接状态；自动日报还会核对大会阶段、订阅启用和群试发状态。暂时不可发送时保留失败记录，条件恢复且仍在允许窗口内可继续操作。人工确认已收到仍独立保留。
- 外部退款的本地发现时间可能晚于渠道创建时间。缺少成功时间时，按渠道创建时间与成功观察上界判断受影响的报告日期；缺少渠道创建时间时保守标注待核对，已确认成功之后的完整日期正常统计。
- 群消息的四个处理按钮使用后台 `/admin/events/...` 路径。预览和历史详情保留相应版本的指标名称，并显示支付订单、待支付、退款处理中，以及大会进行中或结束后的签到数据。
