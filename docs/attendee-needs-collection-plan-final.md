# TokEMS 参会需求收集、首页展示与嘉宾备课方案

> 状态：已确认，已实施，待验收
>
> 方案版本：v1.0-final
>
> 方案日期：2026-08-22
>
> 目标组织与大会：`geo-conference` / `tokems26`
>
> 依据：当前 TokEMS 仓库、现有参会名片链路、个人中心、大会结构化首页、后台大会工作区和生产发布规则

## 1. 结论

本次增加一个独立的“参会需求”环节。报名成功的参会者可以提交 1 至 3 个最关心的问题，并为每个问题选择 1 至 3 个主题标签。新提交默认允许在大会首页公开，默认匿名。用户可以修改公开和匿名设置，也可以在个人中心继续编辑或删除。

公开问题进入大会首页底部的“大家最想解决什么”模块，每页固定展示 10 条。后台增加大会级“参会需求”页面，供运营人员查看、筛选、修改、隐藏、恢复、软删除和导出。首版通过标签筛选和嘉宾版 CSV 把问题交给相关嘉宾，帮助嘉宾调整 PPT 和分享内容。

本方案复用现有报名资格、用户身份、参会名片授权、公共接口限流、后台权限、审计日志和大会发布快照。首版增加两张表，不增加第三方服务、环境变量、运行时或新的权限类型。

## 2. 审查后锁定的补充决策

| 审查项           | 最终决策                                                                             |
| ---------------- | ------------------------------------------------------------------------------------ |
| 问题与标签的关系 | 标签保存到每个问题，避免 3 个不同问题共用一组含义模糊的标签                          |
| 多人购票         | 只有已经认领该报名名额的参会者可以提交，购票人不能替其他参会者填写                   |
| 参会名片关系     | 参会需求拥有独立公开授权，用户可以匿名公开问题，同时保持参会名片私有                 |
| 默认公开         | 默认值只出现在未保存表单中，用户点击保存并提交当前授权版本后才会真正公开             |
| 实名展示         | 取消匿名时单独确认署名，只展示署名，不展示公司、职位和联系方式                       |
| 后台隐私权限     | 管理员可以收紧公开范围，不能替用户开启公开，也不能把匿名问题改为实名                 |
| 后台删除         | 页面显示“删除”，数据层采用可审计的软删除，管理员可以恢复                             |
| 用户删除         | 用户可以删除单个问题，也可以删除全部参会需求。账号删除时永久清除问题正文和署名       |
| 退款与取消       | 部分退款继续有效，全额退款、报名取消、票券取消、账号封禁会立即停止公共展示           |
| 参会人更换       | 原报名进入 superseded 状态时，需求立即停止展示并清除公开署名，新参会者不会继承原问题 |
| 后台编辑冲突     | 用户和管理员共用乐观并发版本，旧页面保存时返回 409，避免覆盖另一方的新修改           |
| 首页换页         | “每 10 行自动换页”按数据自动分页处理，访客通过上一页和下一页切换，不使用定时轮播     |
| 嘉宾交付         | 首版导出不含手机号、邮箱和用户内部标识的嘉宾版 CSV，嘉宾无需登录 TokEMS              |
| 标签配置         | 首版使用 `tokems26` 固定主题词表，稳定代码进入契约。大会级自定义词表进入后续迭代     |
| 首页类型         | 首版支持当前 `structured` 结构化首页，导入型 HTML 首页不进入本次范围                 |

## 4. 目标和成功条件

### 4.1 产品目标

- 让参会者明确表达希望大会解决的问题。
- 让组委会在大会前看到真实需求和主题热度。
- 让嘉宾拿到按主题整理的问题，调整演讲重点、案例和 PPT。
- 让公开问题成为大会首页的真实内容，帮助潜在参会者理解本届大会关注什么。
- 保留清楚、可撤回、可追溯的公开和匿名授权。

### 4.2 首版成功条件

- 报名成功用户能在第 6 步提交、跳过、修改或删除参会需求。
- 每次提交包含 1 至 3 个问题，每个问题包含 1 至 3 个标签。
- 新表单默认公开、默认匿名，保存前提供公开预览。
- 首页每页展示 10 条有效问题，匿名和实名返回字段严格分离。
- 后台可以完成搜索、筛选、修改、隐藏、恢复、软删除和 CSV 导出。
- 组委会能够在后台按主题筛选并导出嘉宾版问题清单。
- 退款、取消、票券失效、账号封禁和参会人更换能及时停止公开展示。
- 新页面和接口通过跨组织、跨大会、跨报名、内容安全和统计隔离测试。

## 6. 用户与状态边界

### 6.1 谁可以提交

满足以下条件的参会者可以新建需求：

- 报名记录属于当前组织和当前用户。
- 报名记录没有被新的报名记录取代。
- 报名状态为 `confirmed`、`checked_in` 或 `completed`。
- 订单状态为 `paid` 或 `partially_refunded`。
- 收费订单存在可信的支付成功记录，免费订单已经确认。
- 电子票状态为 `valid` 或 `used`。
- 用户账号状态为 `active`。
- 当前大会模板启用了 `flow.attendee-needs`。

多人购票场景以报名记录的 `customer_user_id` 为准。购票人只能维护自己的报名需求。其他参会者认领名额后，使用自己的账号填写。

### 6.2 资格失效后的行为

| 状态变化     | 公共首页                     | 用户侧                         | 后台                                     |
| ------------ | ---------------------------- | ------------------------------ | ---------------------------------------- |
| 部分退款     | 保持展示                     | 可继续编辑                     | 正常管理                                 |
| 全额退款     | 立即隐藏                     | 可查看、关闭公开或删除已有内容 | 显示资格失效原因                         |
| 报名取消     | 立即隐藏                     | 可查看、关闭公开或删除已有内容 | 显示资格失效原因                         |
| 票券取消     | 立即隐藏                     | 可查看、关闭公开或删除已有内容 | 显示资格失效原因                         |
| 账号封禁     | 立即隐藏                     | 登录受现有账号规则限制         | 显示资格失效原因                         |
| 大会停止公开 | 立即隐藏                     | 已有内容保留                   | 正常管理                                 |
| 管理员隐藏   | 对应问题隐藏                 | 显示原因，仍可编辑和删除       | 可恢复                                   |
| 管理员软删除 | 对应问题隐藏                 | 显示已被移除，替代问题进入复核 | 可恢复                                   |
| 参会人更换   | 原问题立即隐藏，署名清除     | 原报名不再提供编辑入口         | 保留无公开署名的审计记录                 |
| 账号删除     | 永久移除问题正文、标签和署名 | 无                             | 审计日志只保留资源 ID 和动作，不保留正文 |

资格恢复后，用户主动公开且没有后台隐藏或软删除的问题可以重新展示。参会人更换和账号删除不会自动恢复。

## 7. 用户流程

```text
报名成功
   |
   v
第 5 步：完善参会名片
   |-- 保存名片并继续
   |-- 跳过名片并继续
   v
第 6 步：提交参会需求
   |-- 填写 1 至 3 个问题
   |-- 每题选择 1 至 3 个标签
   |-- 确认公开和匿名状态
   |-- 保存需求
   |-- 稍后填写，先看电子票
   v
保存结果
   |-- 查看电子票
   |-- 返回个人中心
   |-- 返回大会首页
   v
后台按标签筛选和导出
   v
组委会把嘉宾版问题清单交给相关嘉宾
```

参会名片和参会需求分别保存。用户跳过参会名片后仍能提交匿名问题。用户关闭参会名片公开时，已经单独授权公开的匿名问题继续有效。

## 8. 第 6 步页面

### 8.1 路由与页面标题

```text
/account/registrations/:registrationId/needs
```

页面标题：

> 你希望这次大会，帮你解决什么问题？

说明文案：

> 请写下你最关心的问题，最多可以提交 3 个。大会团队会按主题整理给相关嘉宾，帮助他们调整分享重点和案例。

### 8.2 问题编辑

- 默认显示 1 个空问题。
- 每个问题去除首尾空白后为 5 至 200 个字符。
- 最多 3 个问题。
- 同一次提交中不允许出现完全相同的问题。
- 每个问题必须选择 1 至 3 个标签。
- “增加一个问题”在达到 3 个后禁用。
- 用户可以删除第 2、3 个问题。
- 删除唯一问题时弹出“删除全部参会需求”确认，确认后关闭公开并软删除全部问题。
- 问题按纯文本保存。URL 可以作为文字出现，前台不转换为可点击链接。
- 输入框显示剩余字数，不在用户输入时自动改写文字。

### 8.3 公开和匿名

新表单默认值：

```text
[x] 允许在大会首页展示这些问题
[x] 匿名展示
```

授权说明：

> 公开后，问题和所选标签会出现在大会首页。匿名状态下，首页只显示“匿名参会者”。大会组委会仍能在后台确认报名归属，用于内容整理和必要的运营处理。

用户取消匿名后显示独立署名输入框：

```text
公开署名：姚金刚
首页将显示为：姚金刚
```

署名使用当前报名姓名并以只读方式展示。需要调整署名时，用户先更新报名资料。该署名只用于参会需求，不受参会名片总开关影响。首页不展示公司、职位、手机号、邮箱、微信号、报名编号或用户 ID，也不自动链接参会名片。

默认值只存在于尚未保存的表单。保存请求必须携带当前授权文案版本。服务端只有在问题有效、公开选项为真、授权版本匹配并记录授权时间后，才会把问题纳入公共查询。

### 8.4 保存结果

保存成功后留在当前页，并显示：

- 已保存的问题数量。
- 当前为公开或仅自己可见。
- 当前为匿名或显示的公开署名。
- 后台隐藏或资格失效原因。
- “查看电子票”“返回个人中心”“返回大会首页”。

保存失败时保留用户输入。两个页面同时编辑产生版本冲突时返回 409，页面提示刷新后重新确认内容，不静默覆盖。

## 9. 个人中心

个人中心不增加新的一级导航。现有“参会名片”区域扩展为“参会资料”，每场有效报名显示两项状态：

- 参会名片：未填写、私有、公开、后台下架或资格失效。
- 参会需求：未提交、私有、匿名公开、实名公开、部分隐藏或资格失效。

每张大会记录提供“编辑参会名片”和“编辑参会需求”两个独立入口。已有需求的取消报名或退款记录继续出现在“参会资料”区域，用户可以关闭公开或删除内容。

## 10. 首页问题模块

### 10.1 位置和模板节点

新增首页区块：

```text
nodeKey: home.attendee-needs
type: attendee-needs
variant: editorial-list
```

区块放在 FAQ 与最终报名模块之间。`home.attendee-needs` 关闭时，首页不请求公共问题接口，数据库内容和后台记录继续保留。区块启用且公开问题为 0 时展示“参会问题正在陆续提交”的空状态。

### 10.2 文案

```text
kicker: ATTENDEE QUESTIONS
title: 这届大会，大家最想解决什么？
subtitle: 这些问题来自已报名参会者，大会团队会按主题整理给相关嘉宾
countLabel: 已收集
emptyText: 参会问题正在陆续提交
```

### 10.3 展示结构

每个问题占一条列表记录：

```text
Q.01  企业内部应该由哪个部门牵头 GEO？
      [企业内部落地] [GEO 团队与人才]             匿名参会者

Q.02  海外 GEO 如何评估投入产出？
      [海外 GEO] [GEO 效果评估 / ROI]             张晴
```

视觉沿用当前大会首页的白底、品牌蓝、编辑式标题和细分隔线。新增模块使用普通 CSS，首页样式继续写入 `conference.css`，账户页和后台使用 Vue scoped CSS，不在新元素上混用 Tailwind 工具类。

展示规则：

- 每页固定 10 条问题。
- 1 至 10 条时不显示分页。
- 11 条起显示上一页、页码、下一页和横向分隔线。
- 排序使用 `first_published_at DESC, question_id ASC`。
- 编辑正文、标签或署名不会改变原排序。
- 新增问题获得新的首次公开时间，进入列表前部。
- 管理员恢复问题后保留原首次公开时间。
- 问题正文完整展示并自然换行，桌面端和移动端均不使用尾部省略号。
- 每条显示 1 至 3 个标签。
- 匿名记录显示“匿名参会者”。实名记录显示用户确认的公开署名。
- 切页后回到模块标题，并把键盘焦点移入新的结果区域。
- 分页按钮具备 40 像素以上点击区域、可见焦点和禁用状态。
- `prefers-reduced-motion` 生效时关闭分页切换动画。
- 页面不定时轮播，也不在用户阅读第 2 页时自动插入新问题。

公共问题按需请求，不进入首页 OG 描述、结构化 SEO 数据或其他页面元信息。第三方统计事件不携带问题正文、标签、署名或报名信息。

## 11. 后台“参会需求”

### 11.1 导航和权限

大会后台导航在“报名管理”后增加“参会需求”：

```text
/events/:eventId/attendee-needs
```

权限沿用：

- `event.registration.read`：查看列表、问题详情和聚合数量。
- `event.registration.manage`：修改、隐藏、恢复、软删除和匿名化。
- `event.registration.export`：导出嘉宾版或内部版 CSV；导出时同时要求读取权限。

本次复用现有 `event.registration.export` 权限。

### 11.2 页面结构

页面顶部显示：

- 提交人数。
- 有效问题总数。
- 当前公开数。
- 匿名公开数。
- 后台隐藏数。
- 软删除数。

列表支持：

- 按问题正文、公开署名、报名姓名和报名编号搜索。
- 按主题标签筛选。
- 按公开、私有、匿名、实名、资格失效、后台隐藏和软删除筛选。
- 按提交时间范围筛选。
- 默认按首次提交时间倒序。
- 表格显示问题、标签、用户公开状态、有效展示状态、提交时间和操作。
- 点击问题后在当前页面打开详情面板，普通查看不使用阻断式弹窗。

### 11.3 管理动作

管理员可以：

- 修改问题正文，仍受 5 至 200 字限制。
- 修改问题标签，每题保持 1 至 3 个。
- 将实名问题改为匿名。
- 隐藏问题并填写原因。
- 恢复已经隐藏的问题。
- 软删除问题并填写原因。
- 恢复软删除问题。

管理员不能：

- 把用户设置为私有的问题改为公开。
- 把匿名问题改为实名。
- 修改用户的公开署名为另一个身份。
- 读取或导出与本功能无关的联系方式。

管理员修改正文或标签后，用户页面显示“大会团队调整了公开内容”和调整原因。后台操作记录操作人、时间、原因、变化字段标识和追踪 ID。审计日志不保存问题正文，也不重复保存手机号、邮箱等无关个人信息。

### 11.4 导出

内部运营版 CSV 包含：

- 问题 ID、问题正文和标签。
- 当前状态和资格失效原因。
- 报名编号、内部用户 ID、报名姓名。
- 提交时间、更新时间和后台处理状态。

嘉宾版 CSV 包含：

- 问题正文。
- 标签。
- 匿名参会者或用户明确公开的署名，可在导出时统一切换为匿名。
- 首次提交日期。

嘉宾版 CSV 永远排除手机号、邮箱、微信号、公司、职位、报名编号、用户 ID、订单和票券信息。两个导出均防止表格公式注入，记录导出人、时间、事件和筛选条件。

## 13. 数据模型

### 13.1 `attendee_need_submissions`

每条报名最多有一份参会需求提交记录。

| 字段                        | 说明                         |
| --------------------------- | ---------------------------- |
| `id`                        | UUID 主键                    |
| `organization_id`           | 组织范围                     |
| `event_id`                  | 大会范围                     |
| `registration_id`           | 报名 UUID，唯一              |
| `customer_user_id`          | 当前参会者用户 UUID          |
| `is_public`                 | 用户是否允许首页公开         |
| `is_anonymous`              | 公共展示是否匿名             |
| `attribution_name`          | 用户取消匿名时确认的公开署名 |
| `consent_version`           | 公开授权文案版本             |
| `consent_at`                | 最近一次有效公开授权时间     |
| `version`                   | 乐观并发版本，从 1 开始      |
| `created_at` / `updated_at` | 创建和更新时间               |

约束和索引：

- `registration_id` 唯一。
- 组织、大会、报名和用户使用复合外键校验范围。
- `is_anonymous = false` 且 `is_public = true` 时，`attribution_name` 必须有值。
- `version > 0`。
- 为 `event_id, is_public, updated_at` 和 `customer_user_id, updated_at` 建立索引。

### 13.2 `attendee_need_questions`

每个问题独立保存，方便分页、筛选和单题治理。

| 字段                        | 说明                         |
| --------------------------- | ---------------------------- |
| `id`                        | UUID 主键                    |
| `submission_id`             | 所属提交记录                 |
| `position`                  | 用户页面顺序，范围 1 至 3    |
| `content`                   | 当前问题正文，5 至 200 字    |
| `tag_codes`                 | 1 至 3 个稳定主题代码        |
| `first_published_at`        | 第一次获得有效公开资格的时间 |
| `admin_edited_at`           | 最近一次后台修改时间         |
| `admin_edit_reason`         | 后台修改原因                 |
| `admin_hidden_at`           | 后台隐藏时间                 |
| `admin_hidden_reason`       | 后台隐藏原因                 |
| `deleted_at`                | 软删除时间                   |
| `deleted_by_type`           | `customer` 或 `admin`        |
| `deleted_reason`            | 删除原因                     |
| `created_at` / `updated_at` | 创建和更新时间               |

约束和索引：

- 同一提交最多保留 3 个未删除问题。
- 未删除问题的 `position` 在提交内唯一。
- `tag_codes` 只接受当前契约定义的代码，去重后长度为 1 至 3。
- 公共列表索引覆盖 `first_published_at, id`，并排除未公开、后台隐藏和软删除记录。
- 标签字段增加 GIN 索引，用于后台筛选。

### 13.3 删除和审计

用户或管理员在普通界面执行删除时写入 `deleted_at`，公共接口立即排除。管理员可以恢复管理员软删除的问题。用户删除的问题不提供后台恢复入口，审计仍保留动作和资源 ID。

账号删除进入现有客户删除流程，永久删除提交、问题正文、标签和署名。审计日志清除正文快照，只保留不含个人内容的动作事实。

### 13.4 迁移

- 迁移只新增表、外键、约束和索引。
- 不回填现有报名数据。
- 已报名用户第一次保存时创建记录。
- 读取未保存需求时返回计算出的表单默认值，不执行数据库写入。
- 使用当前 Drizzle journal 生成下一条有效迁移，保留工作区中已有的 `0053_mute_vulcan` 文件和快照，不手工复用迁移编号。
- 旧应用不读取新表，应用回滚时保留用户已经提交的内容。

## 14. 业务规则

### 14.1 有效公开资格

问题进入公共列表需要同时满足：

- 大会处于公开状态。
- 报名、订单、支付、票券和账号满足第 6 节定义的资格。
- 报名没有被取代。
- 提交记录 `is_public = true`。
- 公开授权版本有效，且存在授权时间。
- 问题没有后台隐藏。
- 问题没有软删除。
- 问题存在 `first_published_at`。

### 14.2 首次公开时间

- 私有问题首次切换为有效公开时写入 `first_published_at`。
- 已公开问题编辑正文、标签或署名时保留原时间。
- 在已有提交中新增问题时，新问题取得自己的首次公开时间。
- 用户关闭公开后保留该时间，再次公开时恢复原排序。
- 管理员恢复隐藏或软删除问题时保留原排序。

### 14.3 参会名片独立性

参会需求与参会名片分别授权：

- 名片私有，需求可以匿名公开。
- 名片公开，需求可以保持私有。
- 需求实名署名来自需求提交记录，不自动读取名片公共字段。
- 首页问题不自动链接用户公开名片。
- 关闭参会名片公开不会改变参会需求状态。

## 15. API 与契约

### 15.1 用户接口

```text
GET    /customer/registrations/:registrationId/needs
PATCH  /customer/registrations/:registrationId/needs
DELETE /customer/registrations/:registrationId/needs
```

`GET` 返回：

- 报名和大会基本信息。
- 是否允许新建和当前资格原因。
- 已保存的问题、标签和状态。
- 公开、匿名、署名和授权信息。
- 后台修改、隐藏和软删除提示。
- 当前 `version`。
- 电子票、个人中心和大会首页入口。

未保存时返回一条空问题、`isPublic = true`、`isAnonymous = true`、当前授权文案版本和 `version = 0`。该响应不创建数据。

资格字段分为 `canCreate` 和 `canPublish`：`canCreate` 同时要求流程节点开启且报名生命周期有效；`canPublish` 表示已有内容当前是否具备公开资格。`effectivePublic` 还会考虑首页发布节点和问题治理状态。

`PATCH` 要求：

- 有效客户会话和 CSRF。
- 报名属于当前用户、组织和大会。
- 至少 1 个、最多 3 个有效问题。
- 每题 1 至 3 个有效标签。
- `version` 与数据库一致。
- 公开时提交当前授权文案版本。
- 实名公开时提交有效署名。

`DELETE` 删除整份参会需求，要求当前版本，执行用户软删除并关闭公开。

### 15.2 公共接口

```text
GET /events/:eventSlug/attendee-needs?page=1
```

响应：

```text
items[]
total
page
pageSize = 10
totalPages
```

每个公开项目只包含：

```text
questionId
content
tags[]
attribution = null | string
firstPublishedAt
```

接口规则：

- 每页固定 10 条。
- 最大页码 10,000。
- `Cache-Control: no-cache, must-revalidate`。
- 使用公共事件现有限流机制，默认每个 IP 每分钟最多 120 次。
- `home.attendee-needs` 关闭时返回空分页，阻止首页正式启用前通过接口枚举问题。
- 匿名项目不返回空字符串形式的姓名字段，响应中完全省略署名。
- 不返回组织 ID、大会内部 ID、报名 ID、用户 ID、订单、票券或联系方式。
- 页码超出范围时返回最后有效页或空结果的行为在契约测试中固定，首版采用空结果并保留准确 `totalPages`。

### 15.3 后台接口

```text
GET   /admin/events/:eventId/attendee-needs
PATCH /admin/events/:eventId/attendee-needs/:questionId
PATCH /admin/events/:eventId/attendee-needs/:questionId/moderation
GET   /admin/events/:eventId/attendee-needs/export.csv
```

后台列表查询支持：

```text
query
tag
visibility
moderationStatus
submittedFrom
submittedTo
page
pageSize
```

修改正文、标签和管理状态都需要当前提交版本。后台修改成功后递增提交版本。正在打开的用户页面若仍使用旧版本，保存时收到 409，从而避免覆盖后台处理结果。

当前大会报名流程在 `member-profile` 后增加：

```text
helpText: 告诉大会团队你最想解决的问题，帮助嘉宾调整分享重点。
```

## 16. 安全、隐私和内容治理

- 公共问题和标签按纯文本渲染，统一转义。
- 用户输入中的 URL 不生成链接。
- 公共响应在服务端删除未授权字段，隐藏字段不进入 JSON、SSR 数据、DOM、日志或 SEO 元信息。
- 默认匿名，取消匿名前显示最终公开署名预览。
- 公开授权保存文案版本和时间。
- 用户关闭公开后，下一次公共请求立即排除。
- 管理员只能收紧公开范围。
- 后台修改、隐藏、恢复、删除和导出写入审计日志。
- 用户保存和删除分别限制为每个限流键每小时最多 30 次，降低软删除历史和审计数据膨胀风险。
- 公共接口限制频率，不提供按用户、报名或组织枚举的参数。
- CSV 字段处理 `=`, `+`, `-`, `@` 等公式起始字符。
- 嘉宾版导出移除所有无关个人信息。
- 第三方网站统计脚本不进入 `/account/registrations/:id/needs`。
- 公共首页与账户页之间如果新增跳转，必须使用新文档导航，继续满足统计脚本隔离规则。
- 日志和后台审计表只记录问题 ID、变化字段标识、状态、原因和追踪 ID，不保存问题全文。

## 17. 失败和边界处理

| 场景                       | 处理                                                         |
| -------------------------- | ------------------------------------------------------------ |
| 保存时网络失败             | 保留页面输入，允许重试                                       |
| 用户和管理员同时修改       | 返回 409，提示刷新后确认新版本                               |
| 问题少于 5 字或超过 200 字 | 字段旁显示错误，不提交                                       |
| 问题超过 3 个              | 客户端阻止，服务端拒绝                                       |
| 标签无效或超过 3 个        | 服务端拒绝，不接受未知代码                                   |
| 用户跳过                   | 不创建数据库记录，不影响报名结果                             |
| 公开时没有授权版本         | 服务端拒绝公开保存                                           |
| 实名公开没有署名           | 服务端拒绝公开保存                                           |
| 资格在保存前失效           | 允许保存为私有或删除，响应说明不能公开                       |
| 管理员隐藏后用户编辑       | 修改内容，继续保持隐藏                                       |
| 管理员软删除后用户编辑     | 已删除问题不参与更新，新增替代问题默认隐藏并等待复核         |
| 公共接口暂时失败           | 首页保留最后一次成功结果，显示轻量重试状态                   |
| 首页当前页因删除变空       | 自动回到上一有效页                                           |
| 主题词表升级               | 稳定代码继续解析，未知历史代码在后台显示原代码并禁止重新选择 |
| 导出内容较多               | 服务端流式生成 CSV，限制在当前大会和当前筛选范围             |

- 公开授权版本和授权时间。

- 复合外键、唯一报名提交和版本约束。
- 公共列表索引和标签 GIN 索引存在。

### 20.2 用户权限和生命周期

- 本人可以读取、保存和删除。
- 购票人不能修改其他参会者的需求。
- 未认领参会者不能提交。
- 跨用户、跨组织、跨大会和跨报名访问全部拒绝。
- 存量有效报名可以首次提交，不需要回填。
- 部分退款保持公开。
- 全额退款、报名取消、票券取消和账号封禁停止公开。
- 参会人更换不会把旧问题交给新参会者。
- 账号删除永久移除正文、标签和署名。

### 20.3 后台治理

- 查看权限和管理权限分离。
- 管理员可以修改正文和标签。
- 管理员可以隐藏、恢复、软删除和恢复软删除。
- 管理员不能替用户开启公开或取消匿名。
- 管理员修改后用户旧版本保存返回 409。
- 用户修改后台隐藏问题后继续保持隐藏。
- 审计日志包含操作人、动作、原因和变化字段。

### 20.4 公共首页

- 0 条隐藏模块。
- 1、10 条不显示分页。
- 11、20、21 条分页正确。
- 每页固定 10 条。
- 编辑不改变首次公开排序。
- 当前页因隐藏或删除变空时回到上一有效页。
- 匿名问题没有身份字段。
- 实名问题只显示公开署名。
- 纯文本内容不能执行 HTML 或脚本。
- 公共接口没有报名、订单、票券、联系方式和内部 ID。

### 20.5 导出和统计隔离

- 内部运营版 CSV 只对管理权限开放。
- 嘉宾版 CSV 不含手机号、邮箱、微信、公司、职位、内部 ID 和报名编号。
- CSV 公式注入字符得到安全处理。
- 导出动作进入审计日志。
- `/account/registrations/:id/needs` 不加载第三方统计脚本。
- 公共页进入账户页时创建新文档。
- 问题正文、标签和署名不进入统计事件。

### 20.6 视觉与可访问性

- 1280、1024、768、375 和 320 像素宽度无横向溢出。
- 问题输入、标签、公开开关、匿名开关和删除操作支持键盘。
- 所有交互目标至少 40 × 40 像素。
- 错误信息靠近字段，保存结果使用可读屏状态。
- 首页分页有可见焦点，切页后焦点位置正确。
- 中文长问题、英文长单词和混合标签不会破坏布局。
- 减少动态效果设置生效。

### 20.7 验证命令

```bash
pnpm build

pnpm test:persistent
pnpm test:operations
pnpm test:visual
pnpm audit:security
```

## 21. 发布与回滚

生产发布前必须完整执行 `docs/production-deployment-runbook.md`。

发布顺序：

1. 功能分支经 PR、评审和 CI 合并到 `origin/main`。
2. 从 `docs/release-records/TEMPLATE.md` 创建本次日期化发布记录。
3. 备份数据库，记录当前提交、容器状态和回滚镜像标签。
4. 执行新增迁移，确认最高迁移和迁移哈希。
5. 发布 API、Web 和 Admin。
6. 保持 `SEED_DEMO_DATA=false` 完成常规应用发布。
7. 经确认后执行规范模板同步，或在后台更新 `tokems26` 当前模板并发布新快照。
8. 先验证第 6 步、用户编辑、后台列表和公共接口，再启用首页区块。
9. 核对容器、本机 HTTP、公网 HTTP、构建版本、迁移哈希和生产数据计数。

回滚策略：

- 优先发布上一版应用镜像。
- 通过大会模板快照关闭 `flow.attendee-needs` 和 `home.attendee-needs`。
- 新表和用户内容继续保留，旧应用不会读取。
- 数据库迁移保持加法兼容，不在常规回滚中删表或覆盖数据库。
- 公共接口故障时关闭首页区块，用户提交和后台数据继续保留。

## 22. 运营指标

账户页禁止加载第三方统计脚本。以下指标通过第一方数据库聚合和审计事实计算：

| 指标         | 定义                        | 首版观察目标 |
| ------------ | --------------------------- | ------------ |
| 需求开始率   | 进入第 6 步 / 有效报名用户  | 建立基线     |
| 需求提交率   | 保存需求 / 进入第 6 步      | 大于等于 40% |
| 平均问题数   | 有效问题数 / 提交人数       | 1.2 至 2.0   |
| 标签覆盖率   | 有有效标签的问题 / 有效问题 | 100%         |
| 公开选择率   | 用户公开提交 / 全部提交     | 大于等于 70% |
| 匿名选择率   | 匿名公开 / 全部公开         | 建立基线     |
| 后台隐藏率   | 后台隐藏 / 全部问题         | 小于 3%      |
| 嘉宾导出次数 | 嘉宾版导出审计记录          | 建立基线     |

首页只记录模块曝光和分页点击等普通行为，不记录问题正文、标签、署名或用户身份。

## 23. 风险和处理

| 风险                     | 处理                                                                |
| ------------------------ | ------------------------------------------------------------------- |
| 默认公开引发误解         | 保存前显示公开预览，默认匿名，授权版本和时间可追溯，关闭后立即隐藏  |
| 用户提交不合适内容       | 纯文本、长度限制、后台隐藏、软删除和审计，首版不自动审核            |
| 管理员修改用户原话       | 要求原因，用户页面显示调整提示，审计保存变化字段标识和操作原因      |
| 三个问题主题不同         | 标签保存到每个问题，后台和嘉宾导出按单题筛选                        |
| 问题公开后资格失效       | 每次公共查询重新校验报名、订单、支付、票券和账号状态                |
| 分页期间数据变化         | 固定首次公开时间，用户主动切页，当前页失效时回到上一有效页          |
| 嘉宾收到个人信息         | 嘉宾版导出默认匿名并移除所有无关个人字段                            |
| 固定标签以后不适用       | 首版只绑定目标大会，第二阶段再增加大会级词表配置                    |
| 当前工作区改动重叠       | 实施前重新冻结状态和差异，逐文件合并，不重置、不清理、不覆盖        |
| 生产模板同步影响业务数据 | 按 Runbook 单独确认模板同步，保持报名、订单、票、发票和库存销量不变 |

## 24. 最脆弱假设

本方案假设首版由组委会在后台按标签筛选，再导出嘉宾版 CSV 交给相关嘉宾。这个方式可以覆盖当前大会的 PPT 定向优化需求，也避免增加嘉宾账号、权限和通知链路。

如果首版就要求嘉宾登录 TokEMS、查看分配给自己的问题并标记处理状态，实施范围会增加嘉宾身份、问题分配、通知、权限和操作审计。该能力归入第二阶段，不影响第一阶段上线。

## 25. 最终确认口径

确认本方案即代表确认以下产品口径：

1. 第 6 步独立成页，可以跳过，不影响报名和电子票。
2. 每人每场大会最多提交 3 个问题，每题选择 1 至 3 个标签。
3. 新表单默认公开、默认匿名，只有保存并记录授权后才生效。
4. 参会需求公开状态与参会名片独立。
5. 首页底部每页展示 10 条，由用户手动切页。
6. 管理员可以修改、隐藏、恢复和软删除，不能扩大用户公开范围。
7. 首版通过标签筛选和嘉宾版 CSV 把问题交给嘉宾。
8. 首版只支持 `tokems26` 的结构化首页和固定 20 个主题标签。
9. 第一阶段完整交付后再启用大会模板节点。
10. 用户确认后进入实施，完成后执行 `/check`，再按生产 Runbook 进入合并和发布流程。
