# 普通用户系统

## 范围

普通用户系统服务大会前台参会人，账号与运营后台员工账号完全分离。账号以组织和中国大陆手机号作为唯一身份，当前支持 `+86` 手机验证码登录。

主要能力：

- 手机验证码快捷登录与首次自动注册。
- HttpOnly 服务端会话、CSRF 校验、多端退出和账号封禁。
- 可选的用户名、真实姓名、邮箱、公司、职位和城市资料。
- 大会报名统一采用 `mobile_otp_required` 手机验证码登录模式。
- 用户中心报名历史、订单、电子票和发票入口。
- 使用有效订单访问链接逐条认领同手机号的历史报名，认领权限一次性消费。
- 后台普通用户新增、检索、资料维护、账号状态、标签、备注、报名和发票历史。
- 用户列表固定每页 20 条并使用页码分页，报名和发票历史继续使用游标分页。
- “用户管理”提供后台管理员目录，并允许超级管理员直接创建、编辑和删除管理员；“系统设置 → 管理员与权限”提供角色、权限和成员状态维护。

## 数据与隐私

核心数据表：

- `customer_users`：组织内手机号身份、状态和活动时间。
- `customer_profiles`：可选用户资料，使用版本号处理并发编辑。
- `public_user_ids`：后台员工与普通用户共用的数字 ID 映射，ID 从 101 开始且删除后不复用。
- `user_id_allocators`：数字 ID 的事务分配器，保证并发注册时不会发出重复编号。
- `customer_auth_challenges`：验证码摘要、有效期、尝试次数和请求来源摘要。
- `customer_sessions`：不透明会话令牌摘要、有效期和撤销状态。
- `customer_consents`：用户协议与隐私政策版本快照。

报名和候补记录通过 `customer_user_id` 关联普通用户。报名同时保存手机号与邮箱规范化字段，历史数据在迁移时完成规范化，系统不会按手机号批量自动归属历史报名。

数据库主键、外键、JWT `sub` 和服务端会话继续使用内部 UUID。后台列表、详情、报名详情、管理员与权限、账号资料和审计日志只展示数字用户 ID。通过数字 ID 读取或修改用户时，服务端会同时校验组织范围和权限。数字 ID 可以被枚举，不能单独作为授权依据。

验证码始终以 HMAC 摘要写入挑战记录。`provider` 模式中的明文只存在于请求处理和通知任务的短生命周期内，通知队列保存加密载荷，通知投递后不在运营数据中保留验证码正文。`fake` 模式固定使用 `123456`，不创建短信投递任务，只允许源码开发或回环地址上的本地 Docker 部署使用。

跨组织关系由数据库复合外键约束。报名、订单和发票使用组织与大会业务元组约束，避免导入或迁移产生关系错配。同一用户或规范化手机号在同一大会仅保留一条业务报名；支付超时后再次提交会恢复原报名与原订单。历史冗余记录通过 `superseded_at` 和 `superseded_by_registration_id` 保留审计关系，不进入常规列表、统计或后续业务操作。

## 多次单票、订单所有权与认领

每次报名创建一个订单和一个参会名额。本人购买会把报名绑定当前账号；代他人购买会把订单绑定购票人，并让报名保持未认领状态。大会的 `additionalPurchaseEnabled` 默认关闭，开启后每个购票人在同一大会最多持有 5 个有效名额。相同 `purchaseIntentId` 的重试返回原订单，内容冲突返回 `409`。

购票人管理支付、退款和发票。参会人通过独立的一次性认领令牌绑定报名，只能查看本人报名、电子票和参会名片。认领令牌原文以密封载荷进入 Outbox，数据库只保存摘要；订单访问令牌不具备参会人认领权限。认领完成后，购票人不能再修改该名额的手机号和邮箱。

账号删除会把现代订单的购票人外键置空并保留购买快照、`purchaseIntentId`、订单、票和发票。该订单不会转交给已认领参会人。迁移前的历史订单同时缺少购票人字段和购买意图时，可以按原报名账号恢复财务访问。

## 频率与会话策略

- 验证码有效期：5 分钟。
- 单个验证码最多验证 5 次。
- 同一手机号每小时最多请求 5 次。
- 同一手机号跨组织每小时最多请求 8 次，可通过环境变量调整。
- 同一请求来源每小时最多请求 20 次。
- 组织每日默认上限 10,000 次，可通过环境变量调整。
- 用户会话采用浏览器支持的 400 天长期有效期。主动退出、账号封禁、清理浏览器数据或到期后立即失效。
- 过期 24 小时以上的验证码挑战自动清理。
- 过期或撤销 7 天以上的会话自动清理。
- 修改资料、提交发票、认领报名和退出操作需要 CSRF 令牌。

## 后台权限

- `customer.read`：查看普通用户列表、详情、报名和发票历史。
- `customer.manage`：新增普通用户，编辑资料、标签和内部备注。
- `customer.status.manage`：启用或封禁账号，组织管理员默认拥有。
- `customer.export`：导出包含完整手机号的用户目录，默认仅组织管理员拥有。
- `customer.delete`：永久删除普通用户账号，默认仅组织管理员拥有。

大会负责人可以新增、查看和维护本组织普通用户资料，无权批量导出、封禁或删除全局账号。后台新增用户会预建手机号账号和基础资料，不会建立登录会话，用户首次登录仍需通过短信验证码。用户列表、用户详情、新增、编辑、导出和删除接口均以后台会话中的组织身份做隔离。导出同时需要 `customer.read` 和 `customer.export`。删除账号会撤销会话并解除报名、候补记录的账号关联，订单、发票和大会业务历史继续保留；同一手机号后续验证时会创建新账号，原历史不会自动关联。

由不可变员工 UUID `ADMIN_USER_ID` 标识的超级管理员可以在“用户管理”直接填写用户名和密码创建新的组织管理员，也可以修改其他管理员的用户名、单独重置密码或删除其当前组织成员关系。默认值与种子超级管理员 ID 相同；自建初始化账号时需要显式设置。用户名统一转换为小写，需为 3～32 个字符并以字母开头，只能包含字母、数字、下划线和短横线；密码至少 8 个字符且最多 72 个 UTF-8 字节。超级管理员不能在管理员目录中编辑或删除自己，组织必须保留至少一名启用中的超级管理员。所有凭据变更和删除操作都会写入审计日志。

用户名管理员沿用现有后台员工账号表，并使用 `@staff.tokems.invalid` 保留域生成内部账号标识。该标识只存在于服务端凭据存储与登录查询，公开身份契约返回 `username` 和空联系邮箱；邮件投递链路需要排除该保留域。后台员工用户名和密码属于整套部署中的全局登录身份，因此修改凭据会同步影响该账号在所有组织的登录，并在每个关联组织写入审计与事件记录。用户名或密码更新会立即终止该账号在全部组织的现有后台会话，同时取消旧登录标识关联的待接受邀请。成员关系停用、启用、删除或重新创建都会轮换当前组织的会话版本。删除管理员只撤销当前组织访问权限，账号在其他组织的成员关系继续保留。

具备 `customer.read` 权限的后台用户可以在用户列表查看完整手机号。用户目录导出沿用当前筛选条件，导出全部匹配结果，不受当前页限制，最多导出 10,000 条。导出记录会写入审计日志。

## 必需环境变量

生产环境需要为以下变量配置至少 32 字符的独立随机值：

- `CUSTOMER_OTP_PEPPER`
- `CUSTOMER_SESSION_SECRET`
- `NOTIFICATION_PAYLOAD_ENCRYPTION_SECRET`

其他配置：

- `CUSTOMER_OTP_ORG_DAILY_LIMIT`：组织每日验证码请求上限。
- `CUSTOMER_OTP_PLATFORM_HOURLY_LIMIT`：单手机号跨组织每小时请求上限，默认 8。
- `CUSTOMER_OTP_MODE`：`fake` 使用固定演示验证码 `123456`，`provider` 使用随机验证码并进入通知投递链路。正式部署必须使用 `provider`。
- `NOTIFICATION_WEBHOOK_URL`：短信或邮件通知服务入口。

## 上线步骤

1. 备份 PostgreSQL。
2. 配置普通用户系统的三个生产密钥和短信通知服务。
3. 执行 `pnpm db:migrate`。
4. 在“系统设置 → 账号与合规”填写协议地址和版本。
5. 确认存量大会和新建大会均使用手机号验证码登录。
6. 保存大会报名设置，使统一登录模式进入当前公开快照。
7. 验证验证码登录、报名、用户中心、发票、后台用户详情和账号封禁。

## 本地演示数据

本地环境的管理员用户 ID 固定为 101。`DEPLOYMENT_MODE=local` 时，种子脚本会创建 10 条普通用户数据，用户 ID 为 102 至 111，其中 6 条关联演示大会报名。下一位新用户会获得 112。

升级已有本地数据库前可以预览测试数据清理范围：

```bash
pnpm db:cleanup-local-demo
```

确认备份可用后执行清理，再迁移并重建演示数据：

```bash
pnpm db:cleanup-local-demo -- --confirm
pnpm db:migrate
DEPLOYMENT_MODE=local pnpm db:seed
```

清理工具只接受 `DEPLOYMENT_MODE=local` 和回环地址上的 PostgreSQL。默认命令只输出数量，必须传入 `--confirm` 才会修改数据。生产环境不能运行该工具。

## 回滚说明

普通用户数据表、数字 ID 映射、手机号身份与报名关联字段应持续保留，避免丢失用户历史。应用回滚时不删除用户数据，也不回收已发出的数字 ID。旧应用若仍要求 UUID 形式的公开用户 ID，需要先部署兼容版本，再执行应用回退。
