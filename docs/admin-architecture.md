# 后台管理信息架构

## 目标

后台采用两层工作范围：

1. 管理中心负责大会、用户、共享模板和组织级服务配置。
2. 大会工作台负责单场大会的配置、内容、报名、发票、交易、通知和现场执行。

URL 是大会上下文的唯一业务来源。成员级本地存储和服务端资料只记录最近访问大会，用于登录后的快捷跳转。

管理员登录后优先进入最近管理的有效大会。系统依次检查安全回跳、本浏览器最近大会、服务端最近大会、唯一进行中大会、唯一运营中大会和唯一可用大会。仍有多个候选时进入大会管理列表，由管理员明确选择。

## 视觉主题与氛围

后台延续深蓝编辑式运营台风格，保持宋体标题、低饱和状态色、紧凑表格和清晰数字层级。管理中心强调范围和入口，大会工作台强调状态、任务和操作。装饰性背景保持关闭，层级通过背景明度、细分隔线和有限阴影表达。

## 色彩与字体

- 颜色继续使用 `@conference/ui` 和现有后台样式中的语义令牌。
- 大标题使用现有中文宋体栈，正文和表单使用系统中文无衬线字体栈，代码、编号和状态使用现有等宽字体栈。
- 数字列、金额、倒计时和统计卡使用等宽数字。
- 管理中心与大会工作台共享颜色体系，通过范围标签、面包屑和导航内容区分。

## 页面框架

```text
AdminFrame
├── ManagementShell
│   ├── 大会管理
│   ├── 用户管理
│   ├── 模板管理
│   └── 系统设置
└── EventShell
    ├── 大会概览
    ├── 大会配置
    ├── 嘉宾管理
    ├── 报名管理
    ├── 发票管理
    ├── 订单与退款
    └── 通知中心
```

`AdminFrame` 提供品牌、跳转主内容、用户区、桌面侧栏和移动抽屉。`ManagementShell` 只加载组织范围信息，不展示大会前台入口。`EventShell` 从路由参数读取大会，提供大会切换、管理中心入口和操作记录。大会处于公开状态时才显示独立前台入口，运行时大会尚未完成校验时不使用旧 slug 回退。

大会切换器使用轻量大会列表，显示大会全称、生命周期、日期和城市。当前大会卡片的名称、状态和箭头属于同一个按钮点击区域。非归档大会超过 8 场时提供搜索，并按进行中、筹备与开放、已结束分组。选项使用原生按钮列表，支持 Tab、Shift+Tab 和 Escape；归档大会通过大会管理列表访问。

## 路由

### Agent Access

- `/agent-authorizations/:authorizationId`：展示实例、组织、客户端、scope、DPoP 指纹与连接策略，超级管理员完成密码 step-up 后批准或拒绝。
- `/agent-operations/:operationId`：展示动作、目标、风险、原因、正文哈希、前态指纹、脱敏差异、影响和有效期，受控或关键操作在此批准。
- 组织设置中的 Agent 连接面板：查看连接状态、最后使用时间、到期时间和 scope，支持单连接撤销与 step-up 后全部撤销。
- 连接面板同时展示活跃连接、待审批设备、24 小时操作量、未知结果数和 refresh token 重用等安全告警摘要。

授权页和操作审批页保持单一主要动作、明确危险提示与移动端纵向布局。浏览器会话承担人类审批，Agent token 无法调用审批接口。

所有授权、策略、撤销和关键 operation 审批入口仅允许配置的超级管理员使用。审批摘要由服务端根据授权或 operation 的当前字段重新计算，页面提交的摘要只用于一致性校验。

### 管理中心

| 路由                            | 页面       |
| ------------------------------- | ---------- |
| `/manage/events`                | 大会管理   |
| `/manage/users`                 | 用户管理   |
| `/manage/templates`             | 模板管理   |
| `/manage/templates/:templateId` | 模板编辑器 |
| `/manage/settings`              | 系统设置   |

旧 `/manage/members` 自动跳转到 `/manage/users`。

系统设置按必要运营能力组织为六个顶部页签：

1. 公开网站：站点身份、搜索摘要、页脚和备案信息。
2. 支付服务：微信支付商户凭据、Native 通道和连接验证；JSAPI、H5 与 OAuth 放在折叠的高级区域。
3. 短信服务：阿里云账号、签名、分组模板和发送测试。
4. 网站统计：识别并确认百度统计、Google Analytics 4 或 Umami 完整代码。
5. 账号与合规：用户协议、隐私政策及其版本存证。
6. 管理员与权限：管理员邀请、角色、状态和高级权限集。

桌面端在页头下方使用水平文字页签，移动端使用原生下拉选择。设置详情使用最大 1120px 的单栏容器。旧的组织默认项、统计与数据、集成状态路由保留跳转兼容，对应配置数据不做删除迁移。

新建大会显式使用 `Asia/Shanghai` 和 `mobile_otp_required` 初始值，并选择当前列表中第一个已发布模板。已存储的组织默认时区、默认模板和默认登录方式只用于兼容旧数据。公开站点继续渲染已存储的品牌、SEO、页脚和合规字段。经管理员确认的组织级网站统计配置会写入公开首页、FAQ、会员、嘉宾和合作页面的 Head；报名、账户、订单、发票、票证、独立支付入口、后台和 API 保持隔离。公开区域与敏感区域之间的前端导航使用新文档加载，防止已执行的第三方统计运行时跨越页面边界。

### 大会工作台

| 路由                                                              | 页面                             |
| ----------------------------------------------------------------- | -------------------------------- |
| `/events/:eventId/overview`                                       | 大会概览                         |
| `/events/:eventId/settings/general`                               | 基本信息                         |
| `/events/:eventId/settings/site`                                  | 兼容跳转至基本信息的公开页面区块 |
| `/events/:eventId/settings/registration`                          | 报名设置                         |
| `/events/:eventId/settings/form`                                  | 表单与条款                       |
| `/events/:eventId/settings/changes`                               | 修改记录                         |
| `/events/:eventId/speakers`                                       | 嘉宾管理                         |
| `/events/:eventId/speakers/new`                                   | 新建嘉宾                         |
| `/events/:eventId/speakers/:speakerId`                            | 编辑嘉宾资料                     |
| `/events/:eventId/registrations`                                  | 报名管理                         |
| `/events/:eventId/registrations/cooperation-requests/:requestId?` | 合作申请列表与详情               |
| `/events/:eventId/invoices/:invoiceId?`                           | 发票管理与路由化详情             |
| `/events/:eventId/orders`                                         | 订单与退款                       |
| `/events/:eventId/notifications`                                  | 通知中心                         |
| `/events/:eventId/activity`                                       | 操作记录                         |

`eventId` 是全局唯一的正整数，范围为 `101`–`2147483647`。正式大会从 `101` 开始，创建事务成功后递增 1；归档或删除大会不会释放已经分配的编号。管理后台、API、数据库主外键和异步任务统一使用该数字。

旧路由在一个兼容周期内跳转到新路由。需要大会上下文的旧地址优先使用已验证的运行时大会；没有可用大会时进入统一登录入口重新解析。

### 最近大会偏好

- 本地键使用 `conference.admin.lastEventId.<organizationId>.<publicUserId>`，旧版全局大会键在身份验证后删除。
- `GET /auth/me` 返回 `adminPreferences.lastEventId`，新浏览器可恢复最近一次成功同步的大会。
- 明确选择或进入有效深链接时先更新本地记录，再异步调用 `PATCH /auth/preferences/admin`。
- 页面刷新和唯一候选自动跳转只更新运行时上下文。
- 登录入口解析产生的自动跳转不会被初始路由守卫标记为明确深链接。偏好失效提示保留到目标页面，并按“恢复服务端偏好、沿用本地偏好、进入唯一候选、需要重新选择”说明实际结果。
- 偏好失效或大会归档时清除对应记录，并引导管理员重新选择。
- 大会业务接口继续从 URL 解析 `eventId`，导航偏好不会参与业务范围判定。

## 前台地址与首页默认大会

- 每场大会使用稳定的一级路径 `/{eventSlug}`，例如 `/geo26`；建议使用 4–12 位短地址，接口允许 3–24 位小写字母、数字和连字符。
- 前台根地址 `/` 展示组织选定的首页默认大会，浏览器地址保持 `/`。
- 大会列表展示完整独立地址，并提供复制、“修改短地址”和“设为首页”操作。大会处于公开状态时提供“打开”，草稿和配置中大会显示“尚未公开”。
- 创建大会时可以自定义短地址；留空后系统生成 `e` 加 6 位随机字符。修改成功后旧地址以 308 永久跳转到新地址，并保留在 `event_slug_aliases` 防止其他大会复用。
- `eventSlug` 只能使用小写字母、数字和连字符；`account`、`admin`、`api`、`assets`、`faq`、`healthz`、`invoice`、`order`、`pay`、`register`、`ticket` 为系统保留路径。
- 只有已有公开版本的预发布、报名开放、进行中或已结束大会可以设为首页。
- 当前首页默认大会不能直接进入非公开状态，管理员需要先选择另一场可用大会。
- 首页默认关系存放于组织级 `organization_homepage_events`，前台根地址只读取这份数据库配置。切换操作要求 `org.settings.manage` 并记录审计日志。

## 大会配置

大会配置包含四个页签：

1. 基本信息：名称、简称、主张、介绍、日期、时区、城市、场馆、地址、状态，以及公开页面的模板、首页展示、FAQ、预览和另存共享模板。
2. 报名设置：报名开关、收费模式、票种、价格、容量、权益和前台报名流程；登录方式固定为手机号验证码。
3. 表单与条款：表单字段与条款正文。
4. 修改记录：自动快照、表单与条款存证，以及受权限控制的历史恢复。

大会配置只使用一层页签，各页内部按业务任务纵向分区。嘉宾资料通过大会工作台的独立“嘉宾管理”模块维护，保存时进入内容快照并生成对应公开详情页。议程和 AI 文案继续通过现有 API 与配套 Skill 维护。

大会上线前，配置保存为草稿。大会进入预发布或报名开放状态后，每次有效保存都会自动生成不可变快照并立即切换前台版本；相同内容重复保存不增加版本。运营人员只执行“保存修改”，无需额外发布。前台和报名交易读取当前生效快照，快照固化模板、票种、价格、收费模式、表单和条款。
每次保存以当前生效快照为基线，只更新当前模块。回滚后的后台草稿继续保留，后续修改票种、内容、表单或模板时，其他模块保持回滚版内容。

报名表编辑器优先展示当前生效版本；已保存版本与生效版本不同时提供明确提示。手机号作为登录与参会核验标识固定启用且必填，姓名、邮箱及其他字段可选填、停用或删除。停用字段保留定义与历史数据，新报名及候补不采集该字段；选填字段的空值保持为空。前台预填账号资料后，用户可以自行清空选填值。

报名链接使用 `/register/:eventSlug`，单票种省略票种参数。购买意图保存在当前浏览器会话中，按组织、大会、账号及购买方式隔离；登录时优先恢复账号已有草稿，迁移匿名意图后清理原指针，创建订单后清理完成的意图。历史查询参数链接继续兼容。条款读取当前生效表单的正文与版本，以居中弹窗展示。

票种下架采用可恢复状态。上线大会确认下架后立即生成新快照，前台随即移除该票种；历史版本回滚仍可恢复当时的票种快照，管理员也可重新启用已下架票种。

## 收费模式

大会收费模式包含：

- `free`：所有可发布票种的价格为 0。
- `ticketed`：按票种定价，允许存在价格为 0 的邀请票。

价格为 0 的报名仍创建订单，用于审计、统计和退款边界一致性。订单在报名事务内完成，报名状态转为已确认，库存转为已售并签发电子票。收费订单继续进入支付流程。

## 权限

路由、分组入口和页面动作使用一致的权限映射。分组入口指向当前成员可访问的第一个子页面。客户端根据 `/auth/me` 返回的权限过滤入口和写操作，服务端执行最终授权。

已上线大会中，`event.manage`、`event.content.manage`、`event.inventory.manage` 和 `event.registration.manage` 允许对应模块保存后直接更新前台。`event.site.publish` 继续管理版本回滚和兼容 API 的显式激活操作。管理员分配写权限时，页面会明确提示公开大会的实时生效范围。

| 角色       | 主要范围                                                         |
| ---------- | ---------------------------------------------------------------- |
| 组织管理员 | 用户查看、资料维护、账号状态、模板、发票、系统设置和全部大会能力 |
| 大会负责人 | 用户查看与资料维护、全部大会能力                                 |
| 财务       | 发票、总览、报名读取、订单、退款、导出和审计                     |
| 内容管理员 | 共享模板读取、内容与前台体验实时更新、AI 和通知读取              |
| 运营       | 报名、库存实时更新、通知和签到                                   |
| 只读成员   | 授权范围内的只读页面                                             |

组织必须保留至少一名具备成员管理权限的有效管理员。当前操作者不能停用或移除自己的成员关系，也不能修改自己的角色和权限。非组织管理员只能委派自己已经拥有的权限。

## 组件与交互

- 按钮、输入框和卡片继续使用现有固定圆角等级。
- 导航使用填充背景表达当前项，范围切换使用文字层级和短标签。
- 页面进入动效继续使用现有淡入，交互按压使用轻微缩放。
- 所有图标按钮提供可读标签。
- 表格金额和数量右对齐，文字列左对齐。
- 用户列表完整显示国内手机号，姓名和公司缺失时使用最近报名资料并标明来源。
- 用户导出使用独立权限、确认提示、禁止缓存和审计记录。
- 大会设置页签支持直接链接和刷新恢复。

## 布局与响应式

- 桌面端侧栏固定展示当前范围导航。
- 窄屏使用可关闭抽屉，保留当前范围名称和管理中心入口。
- 管理中心不展示大会选择器、报名搜索和大会前台入口。
- 大会工作台在移动端保留大会切换和管理中心入口。
- 交互目标最小尺寸为 40 × 40 像素。
- 表格在窄屏使用横向滚动或信息卡布局，页面本身不产生横向溢出。发票列表采用信息卡，保证抬头、金额、状态和操作同时可读。

## 深度与层级

页面画布、侧栏、内容面板使用现有背景明度阶梯。表格和结构分组使用细分隔线，浮层和抽屉使用现有柔和阴影。状态颜色只表达业务状态和风险。

## 约束

- 大会业务请求必须显式携带 `eventId`。
- 离线签到队列、批次键和设备凭证按大会编号隔离，旧版无大会归属的浏览器键直接清理。
- 组织范围由服务端身份确定。
- 支付和短信密钥加密保存，浏览器只读取脱敏后的配置状态。
- 导出入口位于对应业务列表。
- 操作记录通过大会工作台工具区进入。
- 管理中心保持四个一级入口。
- 大会工作台保持六个一级入口。
