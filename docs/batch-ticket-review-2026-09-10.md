## 发现与处理

| 项目 | 实际影响 | 修复 |
| --- | --- | --- |
| 付款确认期间的额度 | 已过倒计时、仍有成功资金或未处理通知的 5 人订单，被计为 0 个占用名额，可以继续下单 | 购票额度与库存共用付款保护条件，持续占用额度并引导处理原单 |
| 过期清理候选被占满 | 受保护的多人订单占满每轮候选，后面的普通超时单长期无法关闭 | 先排除付款保护，再按订单去重分页；事务内仍复核最新状态 |
| 旧单处理后的明细状态 | 旧单付款、免费审核通过、关闭、审核拒绝或超时结束后，回填明细保持待处理，影响增购或重新报名 | 各旧入口同步明细状态；旧单成功付款与免费成交记录实际主支付关联 |
| 本人资料保存 | 新名额编辑接口要求请求标识，旧页面的请求未提供，导致保存失败 | 补齐请求标识，同一内容与版本的重试复用标识 |
| 编辑字段与报名表不一致 | 页面显示大会未启用的邮箱等字段，填写后被服务端拒绝 | 新订单使用原报名表的开放字段；规则变化时保留未提交草稿供查看 |
| 旧代填入口的并发覆盖 | 新版单人代购订单经旧入口修改时，可绕过名额版本检查 | 兼容入口必须提供当前报名版本；过期页面拒绝覆盖新资料 |
| 后台用户汇总漏计 | 多人订单没有唯一报名外键，旧关联漏掉发票数量与公开名片数量 | 财务汇总按购票订单归属统计，参会资格经名额明细关联 |
| 现场运营的审核入口 | 内置现场运营角色可审核报名，但没有财务权限，无法使用多人订单审核页面 | 提供仅含逐位参会资料的审核视图；审核响应去除财务信息并处理旧缓存；旧报名详情和列表也按订单查看权限裁剪父订单 |

所有已确认缺陷均先建立可失败的回归检查，再实施修复。新增回归覆盖真实数据库事务与实际页面请求；浏览器接口采用受控测试数据，不调用真实支付或短信渠道。

管理员页面同时完善审核成功提示的保留、审核说明的 500 字限制，以及沿用现有样式的输入框和手机端布局。
