# 后台大会工作区迭代修复记录

> 状态：修复与回归已完成｜日期：2026-08-04｜关联方案：[后台默认大会入口与工作区升级计划](./admin-event-workspace-upgrade-plan.md)

## 修复结论

本轮保持“管理中心 + 大会工作台”的双层级结构和克制的编辑式运营台视觉方向，重点完善默认入口、上下文可信度、操作层级、移动端触控和自动化回归。8 项确认问题均已关闭，最终回归没有遗留阻断项。

## F-01 自动入口与明确深链接混淆

**触发条件**

当前浏览器保存了已归档或不存在的大会，服务端仍有一个有效最近大会。登录入口会清理本地记录并进入服务端大会。

**根因**

入口解析生成的内部跳转发生在初始导航阶段。后续路由守卫只依据“初始导航 + 大会 URL”判断明确深链接，将内部跳转再次标记为用户明确访问。大会外壳随后调用 `rememberEvent()`，写回偏好并清空恢复提示。

**修复**

- 路由记录入口解析得到的目标大会编号。
- 下一次进入同一大会时消费该标记，跳过初始深链接记录。
- 安全 `redirect` 仍在入口解析时显式标记，可继续写入最近大会。
- 新增纯函数生成恢复提示，分别覆盖服务端恢复、本地延续、唯一候选和重新选择。

**回归**

- 新增偏好恢复文案单元测试。
- 手机端真实登录注入失效本地偏好，验证提示可见、按钮尺寸和关闭行为。
- 后台升级烟测确认登录只请求一次大会选项并进入最近大会。

## F-02 非公开大会暴露前台入口

**触发条件**

打开草稿、配置中或已归档大会工作台，或者在大会列表点击该大会的“打开”。

**根因**

前台入口仅根据 slug 生成 URL，没有检查大会生命周期。大会外壳加载期间还使用会话中的旧 slug 作为回退。

**修复**

- 大会外壳只在当前大会完成匹配且处于公开状态时传递前台入口。
- 删除加载阶段的旧 slug 回退。
- 大会列表只为公开状态显示“打开”，其他状态显示“尚未公开”。

**回归**

桌面端和手机端大会列表、大会工作台均纳入视觉遍历；管理中心继续不显示大会前台入口。

## F-03 大会切换卡片存在点击死区

**触发条件**

点击当前大会卡片右侧的生命周期状态标签。

**根因**

状态标签与触发按钮是同级元素，视觉卡片与实际点击范围不一致。

**修复**

将状态标签移入触发按钮，名称、日期、状态和箭头共享同一点击区域，并补充按下反馈。

**回归**

视觉测试分别在桌面端和手机端直接点击状态标签，确认切换面板打开。

## F-04 切换列表语义与键盘模型不一致

**触发条件**

辅助技术读取大会选项，或用户按方向键操作声明为 `listbox` 的列表。

**根因**

组件声明 `listbox/option/aria-selected`，交互设计使用原生按钮的 Tab 顺序，没有实现列表框方向键模型。

**修复**

使用原生按钮列表语义，当前大会改用 `aria-current`。保留 Tab、Shift+Tab、Escape、焦点恢复和对话框标题。

**回归**

静态检查确认伪列表框语义已移除，浏览器回归验证 Escape 关闭及焦点恢复。

## F-05 大会列表信息重复与主操作弱化

**触发条件**

桌面端或手机端浏览大会列表。

**根因**

生命周期被放进右侧操作区，呈现方式接近按钮；“首页默认”在标题和操作区重复；“进入工作台”与辅助操作使用相同次级样式。

**修复**

- 生命周期状态移到大会名称旁。
- 删除操作区重复的默认标记。
- “进入工作台/继续管理”使用主按钮。
- 桌面端操作区使用紧凑横排。
- 手机端存在三个操作时让工作台主操作独占一行，两个操作时保持双列。

**回归**

375px 截图确认列表没有横向溢出，状态与动作层级清晰，主操作触控区域达标。

## F-06 提示关闭按钮触控区域不足

**触发条件**

手机端关闭偏好失效提示。

**根因**

按钮宽高固定为 32px，低于后台设计基线。

**修复**

关闭按钮调整为 40 × 40 像素。

**回归**

浏览器测试读取实际边界尺寸，并验证点击后提示消失。

## F-07 短地址输入框触控高度不足

**触发条件**

手机端打开“修改大会短地址”弹窗。

**根因**

输入框没有独立最小高度和内边距，实际可交互高度只有 17px。

**修复**

输入框最小高度调整为 44px，补充内边距；560px 以下使用 16px 字号，降低移动浏览器自动缩放风险。

**回归**

修复前视觉回归准确报告 `INPUT (274×17)`；修复后同一套 80 场景回归问题数为 0。

## F-08 多确认弹窗导致测试定位冲突

**触发条件**

大会列表同时挂载“设为首页”和“修改短地址”两个确认弹窗组件，视觉测试关闭其中一个弹窗。

**根因**

测试使用全局 `.admin-confirm-dialog` 等待隐藏，严格模式下匹配两个节点。

**修复**

关闭动作与隐藏等待都限定在当前已打开的短地址弹窗实例。

**回归**

大会短地址弹窗在桌面端和手机端均完成截图、关闭和后续页面遍历。
