# 合作伙伴与分销功能实现说明

本文记录《合作伙伴与分销升级最终方案 v3.0》的落地结构、运行边界和验收方法。功能默认关闭，可按大会独立启用。微信商家转账配置继续复用组织现有的 `wechatpay` 集成。

## 功能边界

合作伙伴资格属于大会维度。管理员开通资格后，用户需要确认当前规则版本，推广链接才会参与归因。公开资料发布、目录展示和首页展示由用户授权字段与大会开关共同决定。

后台可按手机号邀请伙伴，姓名、公司和个人佣金比例均可选。已存在的手机号复用同组织账号，新手机号建立普通用户账号，报名状态不影响伙伴资格。资料编辑作用于当前大会；登录手机号由系统用户管理维护。用户只能确认管理员开放的待确认资格，规则换版保留暂停、关闭和独立归因暂停；管理员恢复资格时，尚未接受当前规则的伙伴重新进入待确认。

推广点击通过 `/r/{code}` 建立签名来源。普通访问合作伙伴详情页不会写入归因。来源采用最后一次有效主动点击，有效期默认 30 天；结算消费者使用支付记录锁定的归因修订，后续点击不会改变已付款订单。

佣金按订单聚合并按 `order_item` 拆分明细。每条明细使用整数分与万分位比例计算，结果向下取整到分。退款按 `refund_item_allocations` 冲正对应明细。伙伴自购整单排除；付款后由伙伴认领参会名额时只冲正对应明细。已占用或已结算金额不足以冲正时，差额进入待追偿余额。

退款消费者每次从成功退款分配重新计算明细累计退款额，重复和乱序事件不会再次累加。伙伴存在待追偿余额时，系统暂停新的提现、审核通过、组批和渠道执行，财务核对完成后才能继续。

佣金持久序号按历史最大序号递增，阶梯订单数按仍有有效计佣金额的订单计算。全额退款撤销阶梯计数，零比例的有效订单仍计一单，历史订单费率保持不变。退款或自购认领造成的明细更新、账本冲正和佣金汇总在同一事务内完成，避免中断重放或同时释放佣金时出现不一致。

后台可直接提交补记或冲减佣金。每次调整都先形成佣金申诉记录，再写入追加式账本；单次调整达到 1,000 元时进入待复核状态，由另一位管理员按同一方向和金额完成复核。冲减超过当前可提现余额时，超出部分进入待追偿余额。

## 数据结构

迁移 `0068_partner_distribution_foundation.sql` 和 `0069_outgoing_whirlwind.sql` 建立 18 张领域表，并为支付增加归因修订引用：

- 大会配置与伙伴关系：规则版本、伙伴关系、资料版本、规则确认。
- 推广与归因：推广链接、每日访问、归因修订。
- 财务：佣金汇总、佣金明细、追加式账本、财务事件收件箱。
- 提现：收款人、提现申请、出款批次、出款执行、私有结算文件。
- 运营：佣金申诉、财务对账。

所有支付、退款、佣金、账本、提现与出款写入均使用唯一业务键。余额由账本聚合，不保存可直接覆盖的余额字段。收款账号、OpenID 和姓名使用现有安全包加密；活动收款人指纹在组织内唯一。

## 提现与结算

用户提交提现时，系统在事务中锁定伙伴余额并把税前金额从可提现余额转入占用余额。财务审核填写代扣税费，系统计算预计到账金额并保存结算快照。用户确认税前金额、税费、预计到账金额和收款人版本后，申请进入可组批状态。

结算暂停与新申请、审核通过、组批、批次复核和出款执行共享事务锁，并在锁内重新核对暂停与追偿状态。暂停期间可驳回尚未组批的申请，已发起的渠道查单、回调和终态入账继续运行。人工佣金调整使用同一伙伴余额锁；组批与驳回锁定申请状态，防止已经退回的占用金额再次进入批次。

人工结算与微信结算使用组织和大会两级批次。创建批次与复核批次需要两位不同管理员。人工结算登记到账时需要复核后的批次、最新申请版本和可选的私有回单。微信出款执行同样要求独立复核，未知状态继续占用全部税前金额；已知失败终态释放全部占用金额；只有 `SUCCESS` 记为已到账。

结算单、税务材料与回单保存在私有对象存储。上传使用短期签名地址，确认时校验文件长度、SHA-256 与文件头。用户下载先领取一次性短期令牌，服务端再次校验文件并记录访问审计。

## 微信商家转账

商家转账使用新版 `/v3/fund-app/mch-transfer/transfer-bills`，场景固定为 `1005`。每笔执行保存岗位类型、报酬说明、收款人版本、金额、商户单号、集成修订和凭据版本。

状态机覆盖 `ACCEPTED`、`PROCESSING`、`WAIT_USER_CONFIRM`、`TRANSFERING`、`SUCCESS`、`FAIL`、`CANCELING` 与 `CANCELLED`。回调验证时间戳、平台公钥编号和 RSA 签名，随后使用 API v3 密钥执行 AES-256-GCM 解密。验证后的白名单字段先用微信通知编号幂等写入财务收件箱，再由 Worker 异步更新出款与账本。重复或乱序终态不会回退已经完成的执行。

渠道响应快照使用字段白名单，OpenID 与姓名不会写入明文 JSON、日志或浏览器；收款身份和 OAuth 临时交接数据均加密保存。

微信收款人通过公众号 OAuth 绑定。OAuth state 绑定组织、大会、伙伴、用户、登录会话和用途，十分钟后失效且只能使用一次。回调取得的 OpenID 通过两分钟的一次性交接码返回登录态，浏览器页面不会接收 OpenID。绑定要求最近 30 分钟内建立的登录会话，存在未结清提现时不能更换收款人。

组织支付设置需要同时具备公众号 OAuth、AppSecret、商户号、商户证书、API v3 密钥、平台公钥和商家转账验收状态。配置变更采用双人复核。单笔、单用户每日、商户每日和商户每月限额在创建渠道执行前检查，超限申请保留在队列中或改走人工渠道，系统不会自动拆单。

微信官方接口参考：

- [发起转账](https://pay.wechatpay.cn/doc/v3/merchant/4012716434)
- [转账回调通知](https://pay.wechatpay.cn/doc/v3/merchant/4012712115)
- [用户确认收款](https://pay.wechatpay.cn/doc/v3/merchant/4012716430)
- [按商户单号查询转账](https://pay.wechatpay.cn/doc/v3/merchant/4012716457)

## Worker 与恢复

支付成功、退款成功和参会人认领只写入财务收件箱。Worker 负责消费、佣金释放、规则定时生效、微信主动查单和每日对账。收件箱使用租约、重试时间和完成时间支持中断恢复。

每日支付对账检查有有效归因但缺少佣金的订单；退款对账检查涉及佣金明细但缺少财务事件的成功退款。发现遗漏后写入幂等恢复事件。超过 30 天仍无明确终态的微信执行会生成资金账单核对差异，后台保留商户单号、差异金额和人工销账依据。

财务人员可在后台登记支付、退款或出款账单的核对窗口、笔数、差异金额、证据编号与文件 SHA-256。存在未销账的出款差异时，大会范围的新提现、提现审核、组批、批次复核、人工到账和微信执行都会暂停；差异完成销账并留下审计原因后恢复。

收件箱处理使用一分钟租约。Worker 意外退出后，新的 Worker 会重新领取过期租约并从数据库事实恢复处理。

## 权限与审计

新增权限为：

- `event.partner.read/manage`
- `event.partner.rules.manage`
- `event.commission.read/manage`
- `event.payout.review/execute/export`
- `org.payout.settings.read/manage`

大会负责人通配权限可以管理伙伴并读取佣金。佣金调整、提现审核、出款执行、提现导出和组织商户设置要求精确授权。配置变更、批次复核、人工到账和微信出款记录操作者、前后状态、资源编号与追踪编号。

管理员开通资格时可发送邀请通知。短信通道复用组织阿里云短信配置中的“合作伙伴资格开通”模板，模板变量为 `eventName` 和 `url`；未配置阿里云短信的环境继续使用已有通知 Webhook。通知投递使用伙伴与规则版本组成的业务键，重复开通不会重复发送。

## 页面与统计边界

公开页面包括大会首页合作伙伴区块、合作伙伴目录和合作伙伴详情。详情页保留大会顶部菜单，主体沿用嘉宾和会员详情布局，左侧展示头像、介绍、授权联系方式和图片，右侧展示大会信息、个人海报、二维码与报名按钮。

伙伴关闭搜索收录后，详情接口返回 `X-Robots-Tag: noindex, nofollow`，页面同时输出同义的 robots 元数据。

个人中心提供资料与公开设置、推广素材、收益明细、提现与结算、佣金申诉，沿用个人中心的导航、卡片和表单样式。伙伴海报与会员报名海报共用排版与渲染器，保留合作伙伴身份和专属推广二维码；预览与下载使用同一张 1080 × 1440 图片，并同时受公开授权和海报字段授权约束。

后台大会模块提供概览、佣金订单、提现与对账、分销设置四个标签。概览内展示伙伴列表，并通过居中弹窗邀请和编辑伙伴。校验失败时弹窗保持居中，弹窗内显示错误摘要及对应字段提示。

概览金额与伙伴账户统一从追加式账本聚合：待结算读取 `pending`，可提现读取 `available`，提现处理中读取 `reserved`。佣金订单显示原始佣金扣除冲正后的净额；订单已过等待期不代表该笔金额仍全部可提现，当前余额以账本汇总为准。

推广效果提供累计访问次数、每日去重访问人次、有效订单数和有效成交额。去重访问按日累计，同一访客跨日可能重复计数。有效订单按 `eligibleAmount > 0` 的佣金汇总计数，一笔批量订单计一单；有效成交额直接汇总已扣除退款和不计佣明细的 `eligibleAmount`，避免再次扣减退款。公开图片地址使用相对于 API 基址的 `/events/...` 路径，由前端统一拼接。

伙伴可查看最近 100 条本人申诉及终态处理说明；待二审的决策和调整金额不提前公开。收款渠道按组织能力显示，微信能力未验收时默认人工银行结算，最低提现金额读取当前大会规则。人工收款详情通过独立财务权限按需读取，禁止缓存、记录访问审计并排除 Agent 操作入口；批次复核人与到账登记人必须不同。

`/partners` 可加载公开统计。`/r`、账户、提现和申诉属于敏感区域，禁止第三方统计。公开区域进入敏感区域时保持整页导航边界。

## 配置与上线

生产环境配置以下独立变量：

- `PARTNER_ATTRIBUTION_SECRET`：推广来源签名密钥。
- `PARTNER_PAYOUT_DATA_SECRET`：收款资料加密与结算文件令牌密钥。
- `PAYOUT_PUBLIC_URL`：微信 OAuth 完成后返回合作伙伴中心的公开来源。
- `PUBLIC_API_URL`：微信 OAuth 回调和商家转账通知的公开 API 来源。

首次部署只执行迁移并保持所有大会开关关闭。内部测试大会依次验证规则确认、推广点击、批量订单、部分退款、自购、付款后认领、人工提现、申诉和对账。微信阶段完成商户资质、场景 1005、额度、OAuth 域名、通知地址和运营账户资金验收后，再按组织启用。

微信阶段另有一项启用前门禁：补齐转账执行记录创建后、请求发送前中断的恢复能力。当前查询任务会保留这类记录的占用金额；后台销账只更新对账记录，尚不能完成原执行的证据终态处理。因此当前提交范围按合作伙伴与人工结算阶段验收，微信出款保持关闭。

恢复实现必须复用原商户、原商户单号与原请求参数，并区分精确查无、渠道状态未知和已确认终态。微信官方规定原单幂等重入有效期为三个自然日；超时、裸 HTTP 404 或超过查询期限均不能作为释放资金的依据。具体接口约束见[商家转账常见问题](https://pay.wechatpay.cn/doc/v3/merchant/4013778940)与[按商户单号查询](https://pay.wechatpay.cn/doc/v3/merchant/4012716437)。

回退期间停止新开通、新归因和新提现，Worker 继续消费已经发生的支付、退款、微信回调、主动查单和对账。所有活动出款进入终态后，才可以回退到不理解新状态机的版本。
