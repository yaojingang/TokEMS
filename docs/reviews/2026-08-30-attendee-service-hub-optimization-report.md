# 个人中心大会服务台优化报告

日期：2026-08-30  
基线提交：`2cfc2329607e`  
评审范围：个人中心大会服务台、状态派生、组织者服务、后台配置、桌面端与移动端适配

## 1. 优化目标

本轮将个人中心首屏从单一票卡升级为可执行的大会服务台，让已下单用户在一个区域完成以下核心任务：

- 查看电子票和支付、审核进度；
- 生成个人海报；
- 编辑大会首页名片；
- 提交参会需求；
- 添加大会组织者并确认入群动作；
- 由订单管理人处理发票。

首屏继续保留 TokEMS 原有的编辑式票证语言，状态、动作和大会身份信息形成稳定层级。

## 2. 对标研究与采用原则

本轮参考了以下开源实现：

- [Hi.Events AttendeeTicket](https://github.com/HiEventsDev/hi.events/blob/develop/frontend/src/components/common/AttendeeTicket/AttendeeTicket.module.scss)：采用大会摘要与票根分区、细强调线、明确状态徽标和响应式票面结构。
- [Hi.Events My Tickets](https://github.com/HiEventsDev/hi.events/blob/develop/frontend/src/components/routes/my-tickets/index.tsx)：采用事件摘要、元数据、主次操作的清晰顺序。
- [Pretix order status fragment](https://github.com/pretix/pretix/blob/master/src/pretix/presale/templates/pretixpresale/event/fragment_order_status.html)：采用颜色、图标和文字共同表达状态，并把支付、审核等需处理事项置于高优先级。
- [OpenLuma ticket page](https://github.com/Nishitbaria/openluma/blob/main/app/ticket/%5BeventId%5D/page.tsx)：采用单一主操作和紧凑的日期、地点、参会人、票券信息层级。

采用后的 TokEMS 设计方向为“冷静的编辑式大会票证服务台”：白色卡面、浅灰画布、蓝色主操作、语义色状态、低装饰密度。开源项目提供信息组织方法，视觉细节继续使用 TokEMS 的字号、边框和票根体系。

## 3. 评审中发现并完成的优化

### 3.1 首屏层级

- 主操作改为实心按钮，待支付等紧急状态使用红色主按钮。
- 大会摘要继续使用票面与日期票根分区，缩短票面高度，提升首屏服务入口可见数量。
- “还有 N 项可以完善”改为带状态点的提示胶囊，只统计橙色和红色项目。
- 状态徽标随门票状态使用绿色、蓝色、橙色、红色和灰色语义色。

### 3.2 六项服务入口

- 使用六组统一笔画的 SVG 图标，替换辨识度较低的单字图标。
- 桌面端采用 3 × 2 卡片；无发票权限时保留五项入口，最后一行两张卡片等宽展开。
- 移动端采用两列卡片；五项入口时最后一项占满一行。
- 卡片同时展示模块名称、业务状态、补充说明和操作名称，颜色之外仍可通过文字识别状态。
- 待完善和需处理卡片增加顶部语义强调线和轻背景，已完成、可使用、未开放保持低干扰。

### 3.3 多大会和权限分支

- 大会切换器合并本人报名与代购订单中的大会，选择结果写入 `event` 查询参数。
- 修复本人大会与纯代购大会并存时无法进入订单服务台的问题。
- 发票入口只向订单管理人展示；实际参会人没有订单管理权时首屏不再出现无效发票卡。
- 查询参数指向已删除大会时，页面按待处理、进行中、最近开始和最近结束的规则自动恢复。

### 3.4 状态准确性

- 服务台聚合响应增加最近支付状态。
- 待支付、支付失败、支付关闭和支付确认中使用不同文案与主操作。
- 名片私有状态显示“已设置 · 仅自己可见”，不会进入固定待完善数量。
- 发票、海报和灰色未开放功能继续排除在固定完成度之外。
- 服务台局部状态读取失败时保留常用入口，并提供显式重试。

### 3.5 后台配置体验

- 后台“参会者服务”面板增加未保存状态提示。
- 开启服务时动态校验组织者姓名、微信号、入群说明和二维码。
- 未满足启用条件时列出缺少字段并停用保存动作。
- 保存后按钮显示“配置已保存”，减少重复提交。

### 3.6 隐私和安全

- 组织者二维码只通过登录态受保护接口读取，并校验报名归属、有效报名、有效票券和大会配置状态。
- 二维码响应使用 `private, no-store` 和 `nosniff`。
- 组织者二维码资产使用固定私密标记，当前资产、已替换资产和已移除资产均无法通过通用公开模板图片路由读取。
- 客户端响应不包含对象存储路径。

## 4. 视觉与交互验证结果

- 桌面视口：1440 × 1000，服务入口为 3 列，无横向溢出。
- 移动视口：390 × 844，服务入口为 2 列，无横向溢出。
- 多大会切换：本人大会、无发票权限大会、纯代购大会均通过。
- 键盘操作：服务卡片可获得 `focus-visible` 焦点。
- 浏览器运行：没有控制台错误或页面运行错误。

## 5. 当前结论

本轮优化已经形成稳定的首屏任务层级，视觉密度、状态辨识度和多大会分支均达到进入联调和发布准备阶段的标准。组织者服务默认关闭，运营完成配置后按大会手动启用。

发布前仍需在带 PostgreSQL 的预发布环境执行新增迁移，并使用真实账号覆盖支付、审核、退款、签到、名片下架和二维码越权场景。
